# SECURITY — модель угроз PHP2Shell-RS

## Что инструмент делает

Инструмент выполняет пассивный fingerprint явно указанного HTTP-ответа,
сверяет наблюдения с локальным реестром JSON-профилей, формирует диагностику
и управляет локальными лабораторными контейнерами.

## Что инструмент НЕ делает

- не получает shell и не выполняет команды на исследуемых системах;
- не отправляет OOM-тела, не насыщает worker-ы, не эксплуатирует UAF;
- не читает `/proc/<pid>/mem` и не подделывает структуры PHP;
- не сканирует сети и не перебирает адреса;
- не загружает и не патчит внешний эксплойт-код.

## Встроенные ограничения

| Ограничение | Реализация |
|---|---|
| Разрешённые адреса | loopback всегда; остальные — только из `allowed_addresses`; проверка до запроса |
| TLS | `tls_verify = true` по умолчанию; отключение требует `mode = "lab"` |
| Размер ответа | `http.max_response_bytes` (по умолчанию 2 MiB), потоковый контроль |
| Редиректы | не более `http.max_redirects` (по умолчанию 3) |
| Лаборатории | `mode = "lab"` + compose-файл из whitelist внутри `lab/` |
| Секреты | URL в отчётах деперсонализируются; пользовательские данные не логируются |
| Команды | фиксированные argv, без shell и интерполяции |

## Уровни доверия

- `Confirmed` — поле присутствует в заголовке (например, `X-Powered-By`);
- `Probable` — выведено из тела ответа;
- `Possible` — косвенный признак (SAPI/OS из баннера);
- `Unknown` — данных недостаточно.

Вердикт `sufficient_evidence` требует явного `--arch`, потому что
архитектуру невозможно определить из HTTP. DEFAULT — `insufficient_evidence`.

## Известные ограничения

- Баннеры серверов поддаются подделке; инструмент не пытается их обойти.
- Профили привязаны к конкретной сборке; совпадение версии не доказывает
  совпадение бинарника.
- Отчёт отражает наблюдения, а не доказательство уязвимости.
- Fuzz-цели не запускаются в обычном CI (нужны `cargo fuzz` и nightly).
